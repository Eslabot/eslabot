# 에슬라봇 상세 사용 가이드

**1.0.31 · 화면 갱신 안정성 개선:** 그래픽 처리의 실험적 별도 스레드를 안정 모드로 조정했습니다. Steam이 용량 초과로 이전에 제외한 파일을 매번 다시 보고하지 않아도, 남은 저장본의 일치가 확인되면 로컬 원본을 보존하며 실행합니다. 기존 저장 연동·이어하기·기능은 유지합니다. 선수단의 유물 최적화·등급 기준·프리셋 버튼은 순정 명령 버튼을 가리지 않도록 별도 줄에 표시됩니다. 선수 카드 크기는 유지합니다. 마켓의 복수 직업 필터는 순정 기능을 그대로 사용하며, 에슬라봇의 정렬·등급 기준 전환·미확인 필터도 함께 사용할 수 있습니다.

[소개로 돌아가기](../README.md) · [다운로드](https://github.com/Eslabot/eslabot/releases/latest) · [설치·업데이트 안내](#installation)

게임 내 상단 **도구 ▾** 메뉴에서 기능을 열 수 있습니다. 용병 선택은 조밀한 전체 격자와 이름 검색을 사용합니다. 일부 기능은 구단 관리 화면이나 용병 상세 화면에서 사용할 수 있습니다. 이 문서는 공개된 런처 패키지의 사용 방법을 설명합니다.

**최초 설치에서는 딜미터기·전투 기록 수집·성장 계산·카드 추천이 모두 꺼져 있습니다.** 도구 메뉴의 체크 항목에서 필요한 기능만 켜 주세요. 선택은 다음 실행에도 유지됩니다. F7/F8을 누르면 해당 추천·성장 기능이 활성화되고 창이 열립니다.

## 설치 및 업데이트

### 처음 받을 파일

**[EslabotLauncher-win-x64-1.0.31.zip 다운로드](https://github.com/Eslabot/eslabot/releases/download/v1.0.31/EslabotLauncher-win-x64-1.0.31.zip)**

처음 사용하는 분은 위의 **Windows용 런처 ZIP 하나만** 받으면 됩니다. [최신 릴리스 페이지](https://github.com/Eslabot/eslabot/releases/latest)에서 받는 경우 페이지 아래쪽 **Assets**를 펼쳐 같은 이름의 파일을 누르세요. 초록색 **Code → Download ZIP**은 실행 프로그램을 받는 경로가 아닙니다.

| Releases에 표시되는 파일 | 용도 | 처음 설치할 때 직접 다운로드 |
|---|---|---|
| **EslabotLauncher-win-x64-1.0.31.zip** | 실행 프로그램과 필요한 런타임이 포함된 Windows x64용 포터블 패키지 | **이 파일 하나만 받으세요** |
| eslabot-mod-1.0.31.zip | 런처가 동기화할 때 자동으로 내려받는 모드 파일 | 필요 없음 |
| stable.json | 런처가 읽는 서명된 업데이트 정보 | 필요 없음 |
| Source code (zip) / Source code (tar.gz) | GitHub가 제공하는 저장소 파일 사본 | 실행 프로그램이 아니므로 필요 없음 |

### 처음 실행하는 순서

1. **Windows x64 PC에 Steam과 에스라봉을 설치**합니다. 에슬라봇은 **1.0.31**, 이번 대응 게임은 **0.90.1 / Steam 빌드 26208523**입니다. 지원 목록 밖의 빌드도 기존 실행 버튼으로 시도하며, 알려진 문제 빌드는 차단합니다. 필요한 .NET이 포함되어 있어 별도 개발 도구는 필요하지 않습니다.
2. Steam에서 게임을 실행해 이어서 플레이할 캠페인을 한 번 저장한 뒤 **게임을 종료**합니다. Steam Cloud를 사용하려면 Steam에 로그인하고 게임의 Cloud 설정을 켜 둡니다.
3. 위의 **EslabotLauncher-win-x64-1.0.31.zip**을 다운로드합니다.
4. ZIP을 우클릭해 **압축 풀기**를 선택하고 원하는 로컬 폴더에 **전체 압축을 풉니다.** ZIP 내부에서 바로 실행하거나 EXE만 따로 옮기지 마세요. Steam 게임 설치 폴더에 덮어쓸 필요는 없습니다.
5. 압축을 푼 폴더 안의 **에슬라봇 런처.exe**를 실행합니다. **별도 설치 마법사 없이 런처 창이 열리는 포터블 프로그램**입니다.
6. 런처의 **게임 설치 위치**를 확인합니다. 자동으로 찾지 못하면 **게임 위치** 버튼으로 `eslabong.exe`와 `eslabong.pck`가 있는 게임 폴더를 선택합니다. 게임 폴더는 Steam 라이브러리의 에스라봉 관리 메뉴에서 **로컬 파일 탐색**으로 확인할 수 있습니다.
7. 예전 개발용 모드 저장본을 이어 쓰려는 경우에만, **첫 동기화 전에 기존 모드 가져오기**로 기존 runtime 폴더를 선택합니다. 처음 사용하는 분은 이 단계를 건너뜁니다.
8. **최신 버전 동기화**를 누르고 준비가 끝날 때까지 기다립니다. 최초 준비에는 설치된 게임 데이터를 PC 안에서 약 2GB 복사·검증하므로 시간과 디스크 여유 공간이 필요합니다. 이어서 사용할 저장본을 선택하라는 창이 나오면 원하는 진행본을 선택합니다.
9. **사용 가능** 표시를 확인한 뒤 **에슬라봇 실행**을 누릅니다. 이후 플레이할 때도 이 런처에서 실행합니다.
10. 게임에서 저장하고 정상 종료한 뒤, Steam Cloud를 사용하는 경우 런처의 **Steam Cloud 동기화 완료** 표시까지 확인합니다.

### 이미 사용 중일 때 업데이트

**게임 저장·종료 → Steam 게임 업데이트 완료 → 기존 런처 실행 → 최신 버전 동기화 → 사용 가능 확인 → 에슬라봇 실행**

- 동기화는 공개된 최신 런처·모드와 차단 정보를 받습니다. 게임 패치가 나왔다는 이유만으로 새 빌드의 호환 검증까지 끝나는 것은 아닙니다.
- 보통은 **새 ZIP을 다시 받을 필요 없이** 기존 런처에서 동기화하면 모드와 런처를 함께 갱신합니다. 기존 저장 폴더를 삭제하거나 세이브를 따로 옮기지 마세요.
- **1.0.5의 경로 오류로 동기화 버튼 자체가 작동하지 않는 경우에만** 최신 런처 ZIP을 다시 받아 새 폴더에 전체 압축을 풀고 실행합니다. 기존 저장 폴더는 유지합니다.
- 게임 빌드가 검증 목록과 다르면 **에슬라봇 실행**으로 기존 모드 실행을 시도할 수 있습니다. 별도 확인창 없이 기존 모드로 실행을 시도합니다. 알려진 문제 빌드, 파일 누락·손상, 서명 오류와 저장·Steam Cloud 오류는 이 경고로 우회할 수 없습니다.

## 런처 사용

실행 준비가 끝나 게임 프로세스가 시작되면 준비 진행 막대를 숨기고 **게임 실행 중**으로 표시합니다. 이때 런처의 닫기 버튼은 저장 연동을 유지하며 **최소화**합니다. 게임이 끝나면 저장·Steam Cloud 동기화 진행을 다시 표시하므로, 동기화 완료를 확인한 뒤 런처를 종료해 주세요.

| 버튼·항목 | 설명 |
|---|---|
| 에슬라봇 실행 | 설치된 게임과 승인된 모드의 호환성을 확인하고 전용 모드 환경 실행 |
| 최신 버전 동기화 | 공개된 최신 호환 정보를 확인하고 필요한 모드·런처 업데이트 적용 |
| 게임 위치 | eslabong.exe와 eslabong.pck가 있는 Steam 게임 설치 폴더 지정 |
| 기존 모드 가져오기 | 기존 개발용 runtime의 저장본과 설정 복사. 첫 동기화 전에 사용 |
| 저장 폴더 | 별도로 관리되는 모드 저장본·설정 폴더 열기 |
| 최신 ZIP · 업데이트 | 최신 런처 ZIP과 공개 안내 페이지 열기 |
| 오프라인 실행 | 검증된 로컬 설치본으로 Steam 연결 없는 로컬 캠페인 실행 |

오프라인 실행에서도 설치된 게임과 모드의 버전 일치가 필요합니다. 온라인 동기화에는 인터넷이 필요하고, 오프라인 실행에서는 온라인·Steam 연동 기능을 사용할 수 없습니다.

게임 실행 중에는 저장·종료한 뒤 업데이트해 주세요. 지원 목록 밖의 새 게임 버전도 별도 확인창 없이 기존 실행 버튼으로 시도할 수 있지만, 검증된 것으로 표시하지는 않습니다.

에슬라봇 **1.0.31**의 이번 대응 기준은 Steam 게임 빌드 **26208523 / 0.90.1**입니다. 분리된 시험 환경에서 실제 게임 엔진의 선수단·마켓 UI 조작, 신규 직업 성장·카드 선택과 유물 장착 처리를 확인했습니다. 모든 캠페인·스킬 조합이나 다른 PC까지 검증했다는 뜻은 아닙니다. Steam 업데이트를 완료한 뒤 런처의 **최신 버전 동기화**를 눌러 주세요. 저장 폴더를 삭제하거나 세이브를 옮길 필요는 없습니다.

### 설치 정보 자동 복구 (1.0.6부터)

설치 승인 파일 누락, 중간에 끊긴 설치, 손상된 실행용 파일, 이전 설치 위치가 남은 정보는 서명된 배포본과 현재 게임 빌드를 확인한 뒤 다시 준비합니다. 기존 캠페인 저장본과 모드 설정은 유지하고, 교체한 설치 파일은 로컬 복구 보관함에 남깁니다. 실행 환경 전체를 이동한 경우에도 해당 설치본의 저장 위치를 사용합니다.

1.0.5에서 경로 오류가 나고 **최신 버전 동기화**도 진행되지 않으면 최신 ZIP을 한 번 받아 압축을 풀고 **에슬라봇 런처.exe**를 실행해 주세요. 저장 폴더를 삭제하거나 초기화할 필요는 없습니다. 이후 업데이트는 동기화 버튼을 사용합니다.

인터넷 연결이나 권한 문제, 검증되지 않은 게임 버전, 서명 검증 실패는 임의로 우회하지 않습니다. 작업이 끝나지 않아도 기존 저장본은 보존되며, 원인을 해결한 뒤 동기화를 다시 시도할 수 있습니다.

## 저장과 불러오기

**F5**는 현재 캠페인의 보호 저장점을 만들고, **F10**은 마지막으로 F5로 저장한 캠페인 시점을 불러옵니다. 도구 메뉴의 **빠른 저장 / 빠른 불러오기**로도 사용할 수 있습니다.

**재실행 후 메인 메뉴의 이어하기도 마지막 F5 저장점에서 시작합니다. 단, 순정(Steam)에서 진행한 최신 자동 저장을 가져온 직후에는 그 진행을 먼저 이어합니다. 새로 F5를 누르면 이후부터 해당 F5 저장점으로 이어합니다. 이전 F5 보호 사본은 보존됩니다.** 자동 저장·리롤 성공 저장은 별도로 유지하며 F5를 갱신하지 않습니다. F5 저장점이 아직 없으면 순정 이어하기를 사용합니다. 다른 저장본은 게임의 불러오기 메뉴에서 직접 선택할 수 있습니다. F5 보호 사본 검증에 실패하면 자동 저장으로 조용히 대체하지 않고 이어하기를 차단합니다.

F10은 스킬만 복원하는 기능이 아니라 저장 당시 캠페인 전체로 돌아갑니다. 자동 작업의 내부 저장·성공 저장은 F5 지정 지점을 바꾸지 않습니다. 일반 상태의 F9는 순정 빠른 불러오기를 따르며 자동 작업 중 F9·Esc는 작업 정지에 우선 사용됩니다. 기존 저장본·보호 사본과 Steam Cloud 연동은 유지합니다.

F5/F10의 진행·완료 안내는 화면 맨 아래 한 줄로 잠시 표시됩니다. 저장·불러오기 중에는 중복 입력을 막고, 처리가 끝나면 바로 플레이할 수 있습니다.

불러오기 난수는 게임의 **Allow new rolls when loading** 설정과 해당 기능의 순정 규칙을 따릅니다. 같은 저장본을 불러온다고 모든 카드가 다시 추첨되는 것은 아닙니다.

## 성장 계산·20레벨 성장작

**도구 → 성장 계산**, 또는 **F8**로 엽니다.

1. 20레벨 미만 용병을 선택합니다.
2. 능력치별 중요도와 통과선을 설정합니다.
3. **계산 시작**으로 성장 결과를 탐색합니다.
4. 결과창에서 레벨별 증가량, 최종 능력치, 최대치 대비 비율, 훈련비를 확인합니다.
5. 원하는 결과라면 **적용·저장**을 직접 누릅니다.
6. 원하지 않으면 **미리보기 버리기** 후 조건을 바꿉니다.

상단에는 보유 용병을 모두 표시합니다. 이미 20레벨 이상인 용병은 회색으로 표시되며 선택할 수 없습니다.

미리보기 탐색은 실제 용병·재화·게임 저장본에 결과를 적용하지 않습니다. **적용·저장**할 때 게임의 훈련을 실행하고 결과를 작업 슬롯에 저장합니다. 적용에 필요한 게임 조건과 비용은 충족해야 합니다. 탐색은 F9로 중단할 수 있습니다.

**통과선 %는 성공 확률이 아닙니다.** 각 레벨에서 가능한 최대 성장량 대비 실제 성장량을 중요도로 가중 평균한 점수입니다. 100%는 중요도를 준 능력치가 모두 최대 수준이어야 하므로 충족하기 어렵습니다. 합격한 미리보기가 없으면 **적용·저장**은 비활성화됩니다. 필요하면 통과선을 낮춰 다시 계산해 주세요.

적용·저장을 마치면 현재 캠페인에 결과가 저장됩니다. 별도 CMD나 본 게임 가져오기는 필요 없습니다. Steam Cloud 연동 런처로 실행했다면 게임 정상 종료 후 Steam의 동기화 완료를 확인하세요.

## 육성 목표·카드 추천

**도구 → 카드 추천**, 또는 **F7**로 엽니다.

보유 용병을 고유 ID로 추적하며, 능력치·스킬·강화·특화·마스터리 선택을 비교합니다. 카드 선택창 옆에도 추천이 표시되고, 실제 카드 선택은 사용자가 직접 합니다.

1. 용병 그림을 눌러 대상을 고릅니다.
2. 현재 적용된 직군별 육성안과 목표 수치를 확인합니다.
3. 다른 방향을 원하면 직군안을 바꾸거나 직접 중요도·목표를 설정합니다.
4. 필요하면 미래 선택 경로까지 비교하는 옵션을 조정합니다.
5. 자동 기준으로 되돌리고 싶으면 **자동 추천 복원**을 사용합니다.

게임 0.84.2의 **14·34·54레벨 강화 선택과 Rank I~III**를 반영합니다. 강화 카드에는 Rank와 실제 게임 효과를 표시하고, 효과·쿨타임·역할 등을 이용해 비교합니다. 실제 전투 피해나 승률을 직접 예측한 값은 아닙니다.

카드의 **현재**는 지금 레벨에서 선택했을 때의 개선 점수, **장기**는 설정한 목표 레벨까지 성장한 뒤의 개선 점수입니다. % 피해 증가량이 아닙니다. **경로 비교**는 그 카드부터 이어지는 선택 경로의 평가입니다. ‘검토 N개’는 조사한 후보 수로, 진행률이나 저장·불러오기 횟수가 아니며 밀린 선택이 많으면 시간이 걸립니다.

공략 근거가 부족한 용병은 직군 기본안·추정으로 안내합니다. 미래 자연 성장을 평균으로 가정하는 부분과 제한된 탐색 범위가 있어 모든 상황의 최적해를 보장하지 않습니다. F8에서 실제 성장 결과를 확보하거나 새 카드가 나오면 다시 판단할 수 있습니다.

## 환생 훌훌 리롤

**도구 → 환생 훌훌 리롤**로 엽니다. 시간의 방 용병 카드의 **훌훌 선택**으로도 접근할 수 있습니다.

1. 대상 용병과 훌륭함을 붙일 두 성장 항목을 선택합니다.
2. **목표 훌훌 찾기**로 조합을 탐색합니다.
3. 발견한 조합과 1레벨 결과를 확인합니다.
4. **환생 적용·저장**을 눌러 실제 환생을 실행합니다.
5. 환생 후에는 필요에 따라 F8 성장 계산을 이어서 사용합니다.

탐색 중에는 실제 용병·명성·저장본을 변경하지 않습니다. 적용 시에는 게임의 환생 조건과 비용을 따릅니다. 환생 전 복구본과 환생 후 결과는 별도 작업 슬롯으로 관리합니다. 미리보기 이후 용병이나 구단 상태가 바뀌면 다시 탐색해야 할 수 있습니다.

## 스킬 자동 교체

**도구 → 스킬 교체**, 또는 **F6**로 엽니다.

1. 용병을 고릅니다.
2. **교체할 현재 스킬**과 **원하는 목표 스킬**을 같은 개수로 선택합니다.
3. 목표와 대상을 확인하고 **자동 교체 시작**을 누릅니다.
4. 중단하려면 **F9**를 누릅니다.

원하는 스킬로 교체되었다면 창을 닫고 게임에서 직접 저장해 주세요. 작업 중의 성공 저장·실패 복구는 계속 유지됩니다.

실패 시 최근 성공 상태로 복구하고 다음 시도를 진행합니다. 목표를 얻으면 저장하며, 이미 획득한 목표 스킬을 이후 교체 대상으로 다시 돌리지 않도록 보호합니다. 선택하지 않은 스킬은 교체 계획에서 제외합니다.

이 기능은 미리보기 전용이 아니라 실제 성공 결과를 반영·저장하는 자동 작업입니다. 교체할 대상을 먼저 확인하고, 필요하면 시작 전에 게임의 기본 메뉴에서 수동 저장해 주세요.

### 스킬 작업을 처음부터 다시 설정하기

**기록 초기화 · 새로 설정**을 누르면 현재 용병의 선택 설정과 이전 작업 기록만 지웁니다. 환생 여부와 관계없이 현재 진행·스킬·재화와 실제 세이브는 유지하며, 새 목표를 골라 다시 시작할 수 있습니다.

**이전 성공 저장본 불러오기**는 당시 캠페인 전체를 불러오는 별도 기능입니다. 이후의 환생·레벨·재화도 되돌아가므로 확인창에서 시점을 확인해 주세요. 현재 진행에서 새로 하려면 초기화를 사용하세요.

## 유물 자동 재설정

**도구 → 유물 자동 재설정**으로 엽니다.

1. 재설정할 유물을 선택합니다.
2. 전체 품질 또는 옵션별 목표를 지정합니다.
3. 자동 재설정을 시작합니다.
4. 창 안의 **목표 달성 시 알림음**으로 완료 소리 사용 여부를 선택합니다.
5. 목표 충족 결과를 확인합니다. 성공 결과 저장·확인 후 한 번 울리며, 중단은 **F9·Esc**입니다.

상단의 보유 유물은 등급이 높은 순, 같은 등급에서는 품질이 높은 순으로 표시됩니다. 목록이 길면 유물 영역만 마우스로 드래그하거나 휠로 이동합니다. **장착 중인 유물도 재설정할 수 있습니다.**

시작 상태와 성공 결과를 저장하고, 기준에 맞는 결과를 유지하도록 반복합니다. 장착 유물 처리와 작업 결과 저장은 도구의 절차에 따라 진행합니다. 목표를 만족하는 결과가 언제 나올지는 보장하지 않습니다.

## 유물 프리셋·게임 기본 최적화

**도구 → 유물 프리셋** 또는 용병 상세 화면에서 현재 장착 배치를 등록할 수 있습니다. 용병별 두 슬롯과 유물 아이콘을 비교하며 선택합니다.

선수단 화면에서 장착 유물을 우클릭한 뒤 **이 유물 프리셋 등록**을 선택하면 클릭한 슬롯만 등록합니다. 다른 슬롯의 기존 등록은 유지하고, 등록하지 않은 슬롯은 적용할 때 현재 착용을 유지합니다. **선택 용병 · 현재 유물 저장**은 빈 슬롯까지 포함해 두 슬롯 전체를 저장합니다.

- 여러 용병의 배치를 저장한 뒤 **등록한 용병 전체 적용**으로 일괄 복원합니다.
- 다른 용병이 빌려 쓰는 유물도 동일한 유물 개체를 찾아 회수합니다.
- 중복 등록, 소실·판매 중인 유물, 직업 제한, 열리지 않은 슬롯 등을 적용 전에 확인합니다.
- 유물 잠금·즐겨찾기를 유지하고 게임의 장착·저장 처리를 따릅니다.

모드의 프리셋과 순정 게임의 **선호 유물**은 서로 별도 설정입니다. 프리셋은 등록한 슬롯 배치를 복원하고, 순정 최적화는 게임의 선호 유물 규칙을 따릅니다.

**유물최적화**는 현재 선택한 출전 명단에 대해 게임 기본 최적화를 실행하는 기능입니다. 모드가 모든 조합을 독자적으로 계산해 절대 최적 배치를 확정하는 기능으로 해석하지 말아 주세요.

## 딜·힐 미터기와 전투 분석

### 전투 중 표시

양 팀 용병의 누적 피해와 유효 치유를 숫자와 게이지로 함께 표시합니다. 같은 용병 행에서 위쪽 주황색은 피해, 아래쪽 초록색은 치유이며 오른쪽에서 왼쪽으로 늘어납니다. 양 팀과 두 수치는 같은 눈금을 사용합니다. 용병 그림과 스쿼드 순서로 대상을 구분합니다.

눈금은 누적 수치에 맞춰 여유 공간을 두고 자동으로 조절합니다. 가장 높은 용병의 막대가 범위를 넘지 않으며, 색상별 상대적인 차이를 계속 확인할 수 있습니다.

- **Ctrl+F3**: 딜 미터기 켜기·끄기
- **Ctrl+F4**: 전투 기록 수집 켜기·끄기

화면 표시와 기록 수집은 각각 설정할 수 있습니다.

### 최근 전투 분석

**효율 보기:** DPS/HPS, 받은 피해/초, 유효 치유율, 생존 비율 등 수집 가능한 지표를 제공합니다. 부분 수집·시간 정보가 없는 기록은 해당 값을 계산하지 않고 `—`로 표시합니다. 상세는 보기 전환과 페이지 버튼으로 확인하며 본문 스크롤을 추가하지 않습니다.

**도구 → 전투 분석** 또는 용병 상세의 **최근 전투 분석**에서 핵심 지표·아군 기여도·스킬별 막대·경기 비교를 확인합니다. 캠페인별 최근 60경기를 보관하고 용병 ID로 구분합니다.

- 스킬·직접 식별된 유물별 사용·피해·유효 치유·보호막·CC 기여를 공통 눈금의 막대로 비교합니다. 유물만 보기와 CC 종류별 상세도 제공합니다.
- 수집 가능한 전투에서 초과 치유·식별된 흡혈·생존 시간·동시 광역 피해 확인
- **분석 A / 비교 B**으로 서로 다른 용병의 기록까지 비교합니다. 같은 용병의 두 경기도 계속 비교할 수 있습니다.
- 첫 **전체 분석** 카드에서 현재 보유 용병의 출전당 평균·팀 기여 순위를 10명씩 확인합니다. 이전·다음 버튼으로 페이지를 전환하며, 미보유 용병은 순위에서 제외하되 과거 기록 파일은 보존합니다. 출전 수와 부분 수집 기록 수도 표시합니다.
- 용병별 **전체 평균** 또는 실제 전투를 선택할 수 있습니다. 전투 A와 비교 B의 화살표로 이전·다음 기록을 넘기며, B를 선택하면 같은 영역 안에서 두 기록의 스킬 값·막대를 나란히 표시합니다.
- 전투명에는 리그·아카데미 등 경기 종류를 표시합니다. 상단 용병은 보관된 기록에서 자주 출전한 순으로 정렬합니다.

평균은 해당 용병이 기록된 경기만 사용하며, 기여도는 각 경기의 팀 내 비중을 평균합니다. 기록 수집을 끈 기간은 포함하지 않습니다. 부분 수집과 미관측 정보는 별도로 표시하므로 적은 표본이나 서로 다른 상대의 결과를 단순 성능 순위로 해석하지 마세요.

이 기록은 실제 전투 관측을 바탕으로 합니다. 상대, 레벨, 스킬, 전투 흐름이 달라지면 결과도 달라집니다. 두 경기의 차이를 특정 유물 하나의 확정 기여량으로 해석할 수는 없으며, 일부 지속 효과나 지연 적중은 미분류될 수 있습니다.

## 전투 배속·성능 편의

**도구 → 에슬라봇 설정 → 전투 시작 기본 배속**에서 **순정 게임 설정 사용 / 2배속 / 3배속 / 4배속**을 고릅니다. 선택값은 다음 전투와 게임 재실행 후에도 유지됩니다. 전투 중 바꾼 배속은 해당 전투에만 적용됩니다.

추가 **2·3·4배속**을 지원하며, **전투 시작 카운트다운과 전투 중**에 **Z**로 한 단계 낮추고 **X**로 한 단계 높일 수 있습니다. 일시정지 메뉴·설명창·텍스트 입력 중에는 배속 단축키를 처리하지 않습니다.

미터기와 기록 수집을 필요에 따라 꺼서 수집·갱신 부담을 줄일 수 있습니다. 배속은 전투 진행 속도를 조절하는 기능이며 실제 처리 속도는 PC 성능과 전투 상황에 영향을 받습니다. 게임 버전에 맞춰 일부 전투 효과의 렌더링 오류 방지도 적용합니다.

## 마켓 용병 정렬

마켓 용병 목록의 정렬 메뉴에서 **1레벨 능력치 종합 · 좋은 순 / 낮은 순**을 선택합니다.

최초 체력·전투력·방어·속도의 직업별 1레벨 평가를 같은 비중으로 비교합니다. 성장 스타일이나 잠재력, 현재 레벨의 장비·성장분 전체를 합친 최종 성능 순위는 아닙니다. 초기 기록이 없는 용병은 기록이 있는 용병 뒤에 표시합니다. 이 정렬에서는 샤이니가 먼저 표시됩니다.

## 공통 조작

용병 선택은 각 도구 상단의 그림 카드 격자와 이름·직업 검색을 사용합니다. **ESC**는 열린 도구창을 닫는 데 사용합니다. 자동 작업 정지는 **F9**입니다. 저장·적용 중에는 처리가 끝날 때까지 기다려 주세요.

## 저장본 위치와 기존 모드 가져오기

기본 모드 데이터 폴더는 **`%LOCALAPPDATA%\Eslabot\data`**입니다. 런처의 **저장 폴더**로 열 수 있습니다.

- 최초 설치 시 Steam 게임의 기존 캠페인 저장본을 별도로 복사합니다.
- **1.0.5부터 캠페인 저장을 공식 Steam 저장 폴더에도 자동 반영합니다.** 게임에서 저장하면 기록이 완성된 파일을 확인해 연동하며, 별도의 수동 내보내기는 필요하지 않습니다.
- 온라인 실행 전 Steam의 기존 저장 상태를 확인하고, 게임 종료 후 Steam 클라이언트의 업로드 완료 응답과 해당 파일의 해시를 대조합니다. **‘Steam Cloud 동기화 완료’ 안내를 확인한 뒤 런처를 닫아 주세요.**
- Steam 로그인, 온라인 연결과 해당 게임의 Steam Cloud 사용 설정이 필요합니다. Steam 설정은 프로그램이 임의로 켜거나 바꾸지 않습니다.
- 오프라인·연결 오류·용량 부족 시 서버 업로드 완료로 처리하지 않습니다. 로컬 저장을 보존하고 동기화 대기로 표시하며, 연결을 복구한 뒤 온라인으로 실행·종료하면 다시 확인합니다.
- Steam과 모드 양쪽의 같은 슬롯이 각각 변경됐다면 사용할 진행본을 직접 선택합니다. 시즌·주차를 비교해 선택하고, 취소하면 덮어쓰지 않습니다. 교체 전 파일은 데이터 폴더의 로컬 백업에 보관합니다.
- 프로그램 버전과 데이터 디렉터리는 분리되어 있습니다. 중요한 진행 전에는 게임을 종료한 상태에서 데이터 폴더를 별도로 백업해 주세요.

서버 업로드는 게임 종료 후 Steam의 동기화 절차로 처리합니다. 저장 버튼을 누르는 즉시 서버 업로드까지 끝나는 것은 아닙니다. 모드 설정·전투 분석 기록·배속 설정는 Steam Cloud 대상과 별도로 로컬에 보관합니다. 실제 확인 범위는 Steam 클라이언트의 완료 응답과 원격 캐시 해시이며, 별도 PC에서 서버 저장본을 다시 내려받는 검증은 아직 하지 않았습니다.

1.0.4 이하에서는 이 자동 연동을 지원하지 않으므로 **최신 버전 동기화**로 런처를 갱신해 주세요. 새 배포본의 기본 실행 파일은 **에슬라봇 런처.exe**이며, 예전 설치자의 자동 업데이트·바로가기 호환을 위해 이전 이름의 실행 파일도 함께 포함합니다.

기존 개발용 모드 사용자는 **첫 동기화 전에 [기존 모드 가져오기]에서 기존 runtime 폴더**를 선택합니다. 이전 캠페인과 모드 설정을 함께 가져오기 위한 경로입니다. 이미 새 모드 데이터가 있으면 덮어쓰지 않도록 가져오기를 제한하므로 먼저 순서를 확인해 주세요.


### 선수단 카드 능력치 등급

선수단 카드의 기존 레벨 문구 옆에 `SSAA`처럼 **체력 → 공격 → 방어 → 속도** 순서의 등급을 색으로 표시합니다. 카드 크기와 훈련·아카데미·부상 등의 상태 표시는 유지합니다. 선수단의 **유물 프리셋 적용 버튼 왼쪽**에서 **1레벨 기준 / 현재 기준**을 바꿀 수 있고 선택은 다음 실행에도 유지됩니다. 기존 스카우트 사무소4레벨 무료 평가 해금 조건을 따릅니다.

### 마켓 미확인 필터

마켓의 **미확인만**을 켜면 아직 확인하지 않은 용병을 모아 볼 수 있습니다. **클릭하거나 키보드로 선택하는 즉시** 확인한 것으로 기록합니다. 자동 첫 선택·목록 재구성·단순 마우스 올리기는 포함하지 않습니다. 확인한 행은 다음 목록 갱신부터 제외되며, 기존 신규·스카우터 필터 및 정렬과 함께 사용할 수 있습니다. 기존 열람 기록은 유지하고 과거에 본 용병을 소급해서 추정하지 않습니다.

## 보유 용병 유물 가져오기

1. 선수단 또는 지원되는 전투 스쿼드 선택창의 출전 선수 카드에서 **유물**을 누릅니다. 기존 주장·전술 버튼 영역이 **주장 / 전술 / 유물**로 나뉘며 카드 크기는 유지됩니다.
2. 검색 없이 주전·교체의 모든 보유 용병 카드가 바로 표시됩니다. 받는 용병은 제외되며, 한 페이지에 최대32명씩 표시됩니다. 초상화 옆 위는1번, 아래는2번 유물 슬롯입니다.
3. 가져올 용병을 누르면 그 용병의 **빈 슬롯까지 포함한 두 슬롯을 그대로** 출전 선수에게 가져옵니다. 받는 선수의 기존 유물은 보관함으로 이동합니다.

**잠긴 유물도 이전하며 잠금과 옵션은 유지합니다.** 순정 장착 슬롯 해금·장착 조건·전설 유물 제한을 따릅니다. 장착 정보나 선수단 구성이 바뀌었거나 작업 중이면 이전하지 않으며, 실패 시 기존 장착을 유지합니다. 장착 변경은 순정 저장 경로로 처리하고 기존 Steam 저장 연동을 유지합니다.

## 업데이트·문제 해결

Steam 사전 동기화에서는 이미 동기화돼 새 업로드가 없는 상태와 캠페인 저장이 아직 없는 첫 실행을 구분하며, 실제 온라인 응답과 저장 해시를 확인합니다. 확인되지 않은 상태를 완료로 처리하지 않습니다.


| 상황 | 확인할 내용 |
|---|---|
| 게임 위치를 찾지 못함 | Steam 설치 완료 후 게임 위치에서 eslabong.exe와 eslabong.pck가 있는 폴더 지정 |
| Steam의 기존 저장 동기화를 확인하지 못함 | Steam 온라인 로그인, 게임 Cloud 설정과 동기화/충돌 표시를 확인한 뒤 재시도. 저장 폴더를 삭제하지 마세요 |
| 가져올 캠페인 저장본이 없음 | 원본 게임에서 캠페인을 한 번 저장한 뒤 게임을 종료하고 재시도 |
| 미검증 게임 빌드 | 기존 실행 버튼으로 별도 확인창 없이 시도. 알려진 문제 빌드는 차단하며 호환성을 보장하지 않음 |
| 게임을 종료하라는 안내 | 게임에서 직접 저장하고 종료한 뒤 재시도 |
| 이미 최신 호환 버전 | 정상 상태이며 실행 가능 표시를 확인한 뒤 플레이 |
| 다운로드·검증 실패 | 표시된 오류를 확인하고 다시 동기화. 기존 저장본을 삭제하지 말고 오류 문구 기록 |
| 불러온 뒤 같은 카드가 나옴 | 공식 난수 옵션과 카드별 순정 규칙 확인. 일부 성장 선택은 용병·레벨·환생 횟수에 고정 |
| 새 PC에서 재현되는 오류 | 게임·모드·Windows 버전, 오류 문구, 실행 순서를 함께 전달 |

수정 제안이나 기능 아이디어도 환영합니다. 이 도구는 개인 취미 프로젝트이며, 추천은 참고용이고 새 공식 패치 대응에는 시간이 걸릴 수 있습니다. 초기 공개 검증 범위와 호환 게임 빌드는 [README](../README.md#피드백과-현재-검증-범위) 및 각 릴리스 안내를 확인해 주세요.


## 미검증 빌드 실행과 직전 저장 사본

**최신 버전 동기화 → 에슬라봇 실행 → 표시된 경고 확인 → 실행** 순서입니다. 검증된 게임과 런처의 설치 정보는 구분하며, 빌드 번호만 다르거나 새 실행 파일·네이티브 라이브러리가 포함된 경우도 현재 파일을 대조해 판단합니다. 파일이 실제로 누락되었거나 알려진 문제 팩이면 계속 차단합니다.

미검증 실행 직전 모드와 Steam 로컬 저장을 **한 시점의 사본 한 벌**로 보존합니다. 다음 미검증 실행 때 이 보관본을 교체하며, 자동으로 과거 진행을 덮어쓰지는 않습니다. 보관 위치는 설치 상태 폴더의 `unverified-save-backup/latest`입니다. 이는 F5 보호 저장점과 별개입니다.

서버 연결 실패 시 유효한 서명된 로컬 정보로 판단할 수 있지만, 최신 원격 차단 목록을 확인하지 못했다는 경고를 표시합니다. 손상되거나 서명이 잘못된 응답은 로컬 정보로 덮어 무시하지 않습니다.

## 목록의 능력치 S~F 등급

스카우트 사무소 **4레벨·최대 단계·평가 비용 0** 조건을 충족하면 마켓 용병과 내 클럽 가로 목록의 체력·공격·방어·속도 숫자 위에 큰 S~F 등급을 표시합니다. 순정 평가 기준을 사용하며 무료 평가 해금 전에는 표시하지 않습니다. 개별 용병 평가 구매 이력만으로 이 조건을 우회하지 않습니다.

## 1.0.16 실행 직후 종료 수정

미검증 실행을 허용한 뒤 선택적 전투 효과 패치의 게임 버전 검사가 다시 종료시키는 충돌을 수정했습니다. 효과 패치와 게임 데이터가 다르면 해당 시각 패치만 적용하지 않고 순정 효과로 실행합니다. 손상된 패치, 잘못된 서명, 필수 게임 파일 누락과 저장 연동 오류는 계속 차단합니다.

게임의 DLL 추가 여부도 최초 화면과 동기화에서 같은 기준으로 판단합니다. 미검증 경고가 표시되는 사실 자체가 실행 실패를 뜻하지는 않으며, 새 게임 빌드의 전체 호환성을 보장하지도 않습니다. 런처 하단 안내 공간을 늘려 높은 화면 배율에서 글자가 잘리지 않도록 수정했습니다.


## 1.0.17 온라인 확인 안내 개선

실행 직전 최신 온라인 차단 정보 확인을 패키지 업데이트와 분리했습니다. 정상 조회 시 온라인 실패 경고가 표시되지 않습니다. 실제 연결 실패나 시간 초과일 때만 로컬 서명 정보로 실행할지 묻습니다. 잘못된 서명·만료·차단 정보 순번 되돌림·확인된 문제 빌드는 실행 허용으로 우회하지 않습니다. 오프라인 선택 시에도 이미 받은 차단 정보는 유지합니다.

기존 인게임 기능·속도·저장 및 불러오기 방식은 변경하지 않았습니다.

### 1.0.31 화면 조작 변경
- 선수단 카드 본문은 용병 상세, 하단 세 버튼은 주장·전술·유물로 각각 동작합니다. 기존 카드 크기와 순정 버튼 스타일을 유지합니다.
- 전투 분석 상단의 **분석 A / 비교 B**에서 이름으로 대상을 바로 선택합니다. 카드 격자는 A를 바꾸며, B의 **비교 안 함**을 고르면 단일 분석으로 돌아갑니다.
- 스킬 기여 행 앞에 기록의 정확한 스킬 ID와 일치하는 아이콘을 표시합니다. 옛 기록에 일치 정보가 없으면 잘못 추정하지 않고 빈 표시를 유지합니다.



### 마켓 확인 기록과 표시 유지

목록창에 용병 행이 절반 이상 표시되면 확인한 용병으로 기록합니다. 처음 보이는 목록도 포함하며, 클릭·키보드 직접 선택도 확인 처리합니다. 현재 목록을 즉시 지우지 않고 다음 목록 갱신 때 숨깁니다.

확인했어도 최초 1레벨 체력·공격·방어·속도의 등급 점수 합계가 21점 이상(S=6, A=5, SAAA 이상)이거나 샤이니·챔피언인 용병은 계속 표시합니다. 판매 종료·구매 완료 등 게임 기본 제외 조건과 선택한 신규·스카우터 등의 필터는 그대로 적용합니다.


### 게임 업데이트 후 실행

게임 빌드가 검증 목록과 달라도 별도 확인창 없이 기존 실행 버튼으로 진행합니다. 이미 사용할 수 있는 모드가 있으면 버전 차이만으로 시작 시 동기화를 반복하지 않습니다. 모드 업데이트는 최신 버전 동기화 버튼을 사용하세요.

실행 전 온라인 차단 정보는 짧게 조회하며 연결 지연 시 최근 서명 정보와 알려진 차단 목록을 유지해 진행합니다. 실제 문제가 확인된 현재 게임 빌드, 모드 파일/서명 손상과 저장 충돌 처리는 유지합니다. 지원 목록 밖의 모든 게임 기능이 검증됐다는 의미는 아닙니다.


마켓 상단 [표시: 현재 기준 / 표시: 1레벨 기준]에서 체력·공격·방어·속도의 숫자와 S~F 등급을 함께 전환할 수 있습니다. 선택은 다음 실행에도 유지됩니다. 1레벨 종합 정렬과 SAAA 이상 표시 유지는 항상 최초 1레벨 기준입니다.

## 실행이 안 되거나 오류가 날 때

런처 아래의 큰 **「실행이 안 되나요? 여기 눌러 알려주세요」** 버튼을 눌러 주세요. 어떤 버튼을 눌렀고 어디에서 멈췄는지 적은 뒤, 자동 생성된 진단 내용을 확인하고 **진단과 설명 보내기**를 누르면 됩니다. 실제 접수가 완료되면 접수 번호가 표시됩니다. 전송 실패를 완료로 표시하지 않습니다.

- 설명과 진단은 공개 게시글이 아닌 **비공개 접수함**으로 전달됩니다. 답변받을 이메일·연락처는 선택 사항입니다.
- 버전·게임 빌드·실행 파일 존재 여부·최근 오류 일부만 수집하며, 세이브와 계정 정보·전체 플레이 기록은 자동 첨부하지 않습니다. 진단의 개인 경로·인증 정보는 전송 전에 가립니다. 설명에는 비밀번호나 인증 코드를 적지 마세요.
- 전송 전에 진단을 확인할 수 있으며 동의 없이 자동 전송하지 않습니다. 서버에는 암호화해 보관하고 접수함은 30일 기준으로 자동 정리합니다. 서비스 운영 백업에는 제공업체의 보존 정책이 적용됩니다.
- 런처의 메인 화면이 열리지 않으면 압축을 푼 폴더의 **실행 문제 문의.cmd**를 실행해 문의 창만 열 수 있습니다. EXE 자체가 열리지 않으면 **[웹 문의 페이지](https://eslabot-support.pages.dev/)**에서 증상을 적거나 저장한 진단 JSON을 첨부할 수 있습니다. 인터넷 접속이 안 되면 **진단 파일 저장**을 선택해 두었다가 다시 보내 주세요.

Steam Cloud 용량이 부족하면 Steam에서 일부 저장을 제외할 수 있습니다. 이때 해당 저장은 PC에 남아 있지만 다른 PC에서는 바로 보이지 않을 수 있습니다. 런처는 제외된 파일을 삭제하지 않으며, 실제 저장 충돌이나 확인되지 않은 변경은 계속 보호합니다.

### 유물 프리셋 등록·적용 안내

- 같은 유물은 한 용병에게만 프리셋 등록됩니다. 새로 등록하면 이전 용병의 해당 슬롯 등록만 해제됩니다.
- 판매한 용병·소실된 유물·기존 중복은 정리하고 정상 등록을 적용합니다. 예전 중복은 최신 등록을 우선하며, 같은 시각이면 현재 착용자를 우선합니다.
- [무효 등록 정리]는 등록 정보만 정리하며 실제 장비는 옮기지 않습니다.
- 우클릭 등록은 해당 슬롯만, 두 슬롯 저장은 빈 슬롯까지 복원합니다. 미등록 슬롯은 유지하되 다른 정상 프리셋이 요청한 유물은 회수될 수 있습니다.
- 아직 열리지 않은 슬롯·직업 조건·보상 잠금 등은 해당 요청만 제외하고 안내합니다. 스쿼드 전설 한도·같은 종류 중복 장착 등 전체 제한을 위반하면 장비를 바꾸지 않습니다.
- 잠금/옵션과 기존 세이브는 보존합니다. 적용 후 원하는 상태를 확인하고 직접 F5로 저장하세요.

Steam Cloud 용량 초과로 일부 파일이 제외되더라도 나머지 저장 파일이 모두 일치하면 실행합니다. 해당 파일은 로컬에 유지되며, 이 경우 Cloud 전체 동기화 완료는 표시하지 않습니다.


### 1.0.31 실행·업데이트 오류 대응

- **2GB 파일 오류:** 큰 모드 기록은 메모리에 통째로 읽지 않고 나눠 복사합니다. 비정상적으로 크거나 미완성인 설정은 원본과 이전 정상본을 보존합니다. 기존 저장 폴더를 삭제하지 마세요.
- **Windows 애플리케이션 제어 차단:** 자동 업데이트용 실행파일을 Windows가 차단하면 기존 런처를 유지하고 실행 가능한 기존 모드를 계속 사용할 수 있도록 안내합니다. 이 차단을 모드 호환성 오류로 표시하지 않습니다.
- 이미 이전 런처에서 업데이트가 막히면 [최신 릴리스](https://github.com/Eslabot/eslabot/releases/latest)의 **EslabotLauncher-win-x64-1.0.31.zip**을 받아 전체 압축을 풀고 **에슬라봇 런처.exe**를 실행해 주세요. 세이브를 옮기거나 초기화할 필요는 없습니다.
- 새 ZIP의 실행파일도 Windows 정책으로 차단될 수 있습니다. Windows 보호 기능을 끄거나 회사·학교 정책을 우회하지 마세요. 런처의 **실행이 안 되나요? 여기 눌러 알려주세요**로 증상과 진단을 보내 주세요. 이 배포가 모든 PC의 Windows 허용을 보장하지는 않습니다.

### 1.0.31 순정 진행 가져오기·저장 슬롯 연동 개선

- 순정으로 플레이한 뒤 에슬라봇을 다시 사용할 때 저장 선택창이 나오면, **순정(Steam) 진행 사용**의 시즌·주차를 확인하고 선택하세요. 순정에서 새로 얻은 용병·아이템을 포함한 캠페인 전체를 가져옵니다. 서로 다른 진행의 일부 능력치만 합치지는 않습니다.
- 예전 저장 슬롯이 한쪽에 없더라도 연동 전체를 막지 않습니다. 해당 슬롯의 남은 원본은 보존하고 자동 연동에서 제외합니다. 없는 쪽으로 삭제를 전파하거나 옛 슬롯을 자동으로 되살리지 않습니다.
- 진행 선택을 취소하면 앞선 슬롯이 먼저 덮어써지지 않습니다. 양쪽에 존재하는 진행만 선택할 수 있습니다.
- 순정의 최신 자동 저장을 가져왔을 때는 **이어하기도 가져온 캠페인**으로 연결합니다. 가져온 진행에서 새로 F5를 누르면 그 시점이 새로운 기본 이어하기 기준이 됩니다. 이전 F5 보호 사본은 그전까지 보존합니다.
- 기존 저장 폴더를 삭제·초기화하거나 예전 에슬라봇 저장으로 되돌릴 필요는 없습니다. 로컬 연동과 Steam 서버 업로드 완료 여부는 구분해 표시합니다.
